💾 Fila KV — Pré-orçamentos
Vercel KV: aspen:quote-leads
→
GET /api/quote-leads

#/pre-orcamentos (inbox)

A fila KV é a fonte única de verdade para pré-orçamentos. Toda origem escreve nela. O inbox lê dela.

🔄 Ciclo de Vida do Status
new
→
incomplete
→
ready
→
reviewing
→
converted
ou
discarded

new → ready

Automático na normalização. Se todos os campos obrigatórios (nome, contato, pedido) estão presentes, o lead entra como ready. Senão, incomplete.

ready → reviewing

Operador clica "Em revisão" no inbox. Indica que alguém já está olhando.

reviewing → converted

Ao clicar "Extrair no Auto", o lead vai para a página Auto. Quando o orçamento é gerado no ERPNext, o sistema marca como converted e salva o quotationId.

→ discarded

Operador clica "Descartar". Lead arquivado, não aparece mais por padrão.

🔌 APIs — Detalhamento

/api/typebot-lead-capture

POST · Auth: Bearer TYPEBOT_LEAD_WEBHOOK_TOKEN

Recebe payload do Typebot (via WhatsApp). Faz upsert no ERPNext Lead. Se TYPEBOT_LEAD_CAPTURE_ENABLED=true e não dry_run, também escreve na fila KV com source: "typebot", sourceDetail: "whatsapp".

Também dispara evento Meta CAPI e rejeita leads com quantidade < 30.

/api/quote-leads

GET · Filtros: status, source, q, limit

POST · Auth: Bearer QUOTE_LEADS_INGEST_TOKEN

PATCH · Edita campos e status do lead

CRUD da fila KV. POST é usado pelo site e (futuramente) entrada manual. GET alimenta o inbox. PATCH é usado pelo inbox e Auto page.

/api/evolution-webhook

POST · Webhook da Evolution API

Recebe eventos MESSAGES_UPSERT do WhatsApp. Resolve tokens [ref:token] em Supabase e inicia sessão Typebot via Evolution com variáveis de attribution preenchidas. Não escreve na fila KV diretamente — quem escreve é o Typebot via /api/typebot-lead-capture.

aspen-site: /api/quote

POST · Formulário do site

Fluxo: valida campos → reCAPTCHA → Sanity (quoteRequest) → Resend (2 emails: interno + auto-resposta) → fire-and-forget para dashboard POST /api/quote-leads.

O enqueue para o dashboard é não-bloqueante — falha nele não afeta a resposta ao usuário.

#/pre-orcamentos (Inbox)

Fila unificada de todas as origens. Filtros por status, source, busca textual. Exibe fila à esquerda, detalhe à direita. Ações: Em revisão, Descartar, Extrair no Auto.

Passa o lead para a página Auto via sessionStorage.

#/auto (Extração)

Recebe lead do inbox (ou busca leads manualmente). Usa OpenRouter para extrair dados estruturados do texto. Gera orçamento no ERPNext. Ao concluir, marca lead como converted com quotationId.

#/quotations

Lista de orçamentos já criados no ERPNext. Detalhe com PDF, status, ações.

🔗 Deduplicação & Merge

Chave de identidade

Ordem de prioridade:

1. telefone  → phone:<digitos>
2. email     → email:<email>
3. erpLeadId → erp:<id>
4. externalId → external:<source>:<id>
5. id        → id:<id>

Merge: first-touch

Quando dois leads batem na mesma chave:

• Campos de texto: usa o lead com maior
  score (mais campos preenchidos)
• Nome: prefere o mais longo
• Attribution (gclid, utm_source, etc):
  primeiro a chegar vence (first-touch)
• Status: converted > discarded > normal
• createdAt: mantém o do primeiro registro

Exemplo: WhatsApp + Site

1. WhatsApp chega primeiro:
   nome="Ana", tel="5521999990000",
   gclid="abc", utm_source="google"

2. Site chega depois (mesmo tel):
   nome="Ana Empresa", qtd="150",
   gclid="xyz", utm_source="meta"

Resultado merge:
   nome="Ana Empresa" (mais longo)
   gclid="abc" (first-touch)
   utm_source="google" (first-touch)
   qtd="150" (completa dados)
