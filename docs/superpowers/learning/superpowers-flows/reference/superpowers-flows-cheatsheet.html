Colinha Superpowers

Fluxo padrão, quando usar cada skill e prompts prontos para copiar e colar.

1. Regra de invocação

Se houver 1% de chance de uma skill se aplicar, você DEVE invocá-la antes de responder ou agir. Skills processuais vêm primeiro; skills de implementação depois.

2. Fluxo padrão

brainstorming → writing-plans → executing-plans
ou
subagent-driven-development → finishing-a-development-branch

brainstorming

  • Explora contexto, faz perguntas, propõe 2-3 abordagens.
  • Escreve spec em docs/superpowers/specs/YYYY-MM-DD-<tema>-design.md.
  • Só avança para writing-plans depois que você aprovar o spec.
  • Não escreve código.

writing-plans

  • Transforma o spec em plano de implementação.
  • Salva em docs/superpowers/plans/YYYY-MM-DD-<tema>.md.
  • Cada tarefa é pequena (2-5 min), com arquivos, comandos e critérios.

executing-plans / subagent-driven-development

  • executing-plans: execute em sessão separada, com checkpoints.
  • subagent-driven-development: execute na sessão atual, um subagente por tarefa, revisão após cada.

finishing-a-development-branch

  • Após verificar testes, apresenta opções: merge local, abrir PR, manter branch ou descartar.

4. Anti-padrões comuns

ErroPor que aconteceSolução
Agente recomeça brainstorming em cima de um spec já aprovado O prompt "faça" é ambíguo; o agente não sabe que a fase é execução. Nomeie a skill e a fase explicitamente: "execute o plano X usando executing-plans".
Agente pula para código sem plano Pedido direto de implementação sem spec aprovado. Peça brainstorming primeiro, ou forneça o caminho do plano já escrito.
Nova sessão perde contexto Sessões são isoladas; o agente não lê histórico. Forneça caminho do projeto, caminho do spec/plano e estado de aprovação.
Subagente modifica fora do escopo Prompt sem restrições claras. Inclua "não altere lógica de negócio", "não adicione dependências", etc.

5. Checklist para nova sessão

Antes de pedir execução em uma sessão nova, confirme:
  1. O spec está aprovado? Se sim, não use brainstorming.
  2. Já existe plano? Se sim, use executing-plans ou subagent-driven-development.
  3. As tarefas são independentes? Considere dispatching-parallel-agents.
  4. Você passou o caminho absoluto do projeto e do arquivo?
  5. Você nomeou a skill explicitamente?
